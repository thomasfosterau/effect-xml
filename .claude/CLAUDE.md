## Settings and hooks

`.claude/settings.json` is committed. It wires three hooks, enables the plugins the project uses and carries the settings schema.

- **SessionStart** (`startup` and `resume`; `.claude/hooks/session-start.sh`, 180 s timeout) provisions a checkout for non-interactive use. It installs the global Vite+ CLI at the catalog's `vite-plus` pin with the official installer (npm-provenance and SHA-512 checked; it needs `vite.plus` and `viteplus.dev` on the environment's network allowlist), links `vp` and `vpx` into `~/.local/bin` (the CLI lives under `$VP_HOME` when set, as in the Vite+ container image, else `~/.local/share/vite-plus`), and runs `vp install --frozen-lockfile`. If the installer can't run, `vp` falls back to this checkout's `node_modules` copy. It hydrates no secrets; none are needed, and nothing here can publish.
- **PreToolUse** on `Bash` (`.claude/hooks/fallow-gate.sh`, 900 s timeout) blocks `git commit` / `git push` when `fallow audit --base origin/trunk` (run as `vp exec fallow`) fails; it audits only this checkout and its `.claude/worktrees/*`, skipping any other tree with a notice. It reads the coverage map on disk, and runs `vp run test:coverage` first when the map is missing or older than any file under `src/`, `tests/`, `bench/` or `examples/` (blocking if that fails), so a commit in a fresh worktree is still audited. The script is generated by `fallow hooks install`, with local deviations marked in its header; re-apply them if it is regenerated.
- **PostToolUse** on `Write|Edit|MultiEdit` (inline in `settings.json`, 15 s timeout) runs `vp fmt --write` on every edited `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.css`, `.json` or `.md` file.

## Worktrees

Agent work uses git worktrees under `.claude/worktrees/` (git-ignored), one per branch. A worktree needs its own `pnpm install`.

## What runs in an agent session

Every gate in [CONTRIBUTING.md](../CONTRIBUTING.md#verification) runs in an agent session, with one dependency: `pnpm audit` needs the network. The fallow gate may run `vp run test:coverage` first, which is slow; let it finish.
