Add `XQuery.evaluate`, the XQuery 3.1 / XPath 3.1 evaluator core: it runs a compiled `Query` (or query text) against a context item (an XDM item, or a parsed document or element) and external variables, to an XDM sequence or the first `XQueryError` with its `err:` code and the offset of the expression that raised it. It evaluates path expressions on every axis but `namespace` (`XPST0010`), with name, wildcard and kind tests, predicates (numbers select by position), `/`, `//`, document order and `!`; `union`, `intersect` and `except`; arithmetic with numeric promotion and on dates, times and durations; value, general (with 3.1's `xs:untypedAtomic` rules) and node comparisons; `for`, `let`, `where`, `count`, `some`, `every`, `if`, `switch`, `typeswitch`, `try` / `catch`, ranges, `||`, arrows and string constructors; sequence types with `instance of`, `treat as`, `cast as`, `castable as` and the function conversion rules; inline functions (closures), named function references, partial application and dynamic calls; map and array constructors and lookups; and the prolog's variables and functions. The new `Resolver` service (with `staticResolver` for resources in memory) serves `fn:doc`, `fn:collection` and `fn:unparsed-text`. Built-in functions so far are the core ones (booleans, the focus, counting and taking sequences apart, string and typed values, names, `fn:deep-equal`, `fn:error`, `fn:QName`, documents, collections and texts, map and array accessors); a construct or function not implemented yet fails with the code `NotImplemented` in the new `ImplementationNamespace`. `XdmNode.name` is faster.
